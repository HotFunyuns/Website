A truth table lists every possible combination of true and false for the simple statements in a compound statement, and works out whether the whole statement is true in each case. It is a purely mechanical tool, which is its strength: if you follow the same steps every time, you cannot miss a case.

The method below has five steps. The worked examples use the standard symbols: ¬ for "not", ∧ for "and", ∨ for "or", → for "if… then" and ↔ for "if and only if".

## Step 1: count the variables and the rows

List the different simple statements, usually letters such as p, q and r. Each can be true or false independently, so a table with n variables needs 2ⁿ rows.

| Variables | Rows |
| ---: | ---: |
| 1 | 2 |
| 2 | 4 |
| 3 | 8 |
| 4 | 16 |

Count distinct letters, not appearances. The statement p ∧ (q ∨ ¬p) contains p twice but has only two variables, so it needs four rows.

## Step 2: fill the input columns in a fixed pattern

Write the variables as the first columns. In the first column, make the top half of the rows T and the bottom half F. In the next column, alternate in blocks half that size. Keep halving until the last column alternates every row. For three variables:

| p | q | r |
| --- | --- | --- |
| T | T | T |
| T | T | F |
| T | F | T |
| T | F | F |
| F | T | T |
| F | T | F |
| F | F | T |
| F | F | F |

This is the order OpenStax's *Contemporary Mathematics* uses. *Applied Discrete Structures* writes 0 and 1 instead and runs the other way, listing the rows as the binary numbers 000 up to 111. Either works if you use it consistently. A fixed pattern matters for two reasons: it guarantees every combination appears once, and it makes your table comparable row by row with anyone using the same order.

## Step 3: know the five basic tables

Every compound statement is built from these. Learn them well enough to write them from memory.

| p | q | ¬p | p ∧ q | p ∨ q | p → q | p ↔ q |
| --- | --- | --- | --- | --- | --- | --- |
| T | T | F | T | T | T | T |
| T | F | F | F | T | F | F |
| F | T | T | F | T | T | F |
| F | F | T | F | F | T | T |

Two entries need particular care.

- **"Or" is inclusive.** p ∨ q is true when both are true. If a course means "one or the other but not both", it uses a separate exclusive-or symbol.
- **The conditional is false in exactly one row.** p → q fails only when p is true and q is false. Think of it as a promise: "if you finish the assignment, you can go out." If you do not finish it, the promise has not been broken whatever happens, so the conditional counts as true. The [guide to conditional reasoning](/blog/conditional-reasoning-if-then/) works through this with everyday examples.

The biconditional p ↔ q is true when p and q have the same truth value, which is why it reads "p if and only if q".

## Step 4: add one column per connective, inside out

Break the statement into pieces, starting with the innermost parentheses, and give each piece its own column. Negations come first, then "and" and "or", then the conditional, and the biconditional last. Conventions differ about whether "and" outranks "or": OpenStax's dominance of connectives treats them as equal and reads them left to right, while other conventions put "and" first. Put parentheses around any mix of the two and the disagreement never matters.

**Worked example: (p → q) ∧ ¬q.** The pieces are p → q, then ¬q, then the "and" of the two.

| p | q | p → q | ¬q | (p → q) ∧ ¬q |
| --- | --- | --- | --- | --- |
| T | T | T | F | F |
| T | F | F | T | F |
| F | T | T | F | F |
| F | F | T | T | T |

The statement is true only in the last row, when p and q are both false. That result is the logic behind modus tollens: if p → q holds and q is false, then p must be false. The [rules of inference guide](/blog/rules-of-inference-explained/) builds on it.

**Worked example with three variables: (p ∨ q) → r.**

| p | q | r | p ∨ q | (p ∨ q) → r |
| --- | --- | --- | --- | --- |
| T | T | T | T | T |
| T | T | F | T | F |
| T | F | T | T | T |
| T | F | F | T | F |
| F | T | T | T | T |
| F | T | F | T | F |
| F | F | T | F | T |
| F | F | F | F | T |

The final column is false in three rows, each one where p ∨ q is true but r is false. Spotting that pattern is a good habit: once you know when a conditional fails, you can check a finished table by looking only for those rows.

## Step 5: read the final column

The last column answers the question you were asked.

- **All T:** the statement is a tautology, true whatever its parts are.
- **All F:** it is a contradiction.
- **A mix:** it is a contingency, true in some cases and false in others.

[Tautology, contradiction or contingency?](/blog/tautology-contradiction-contingency/) covers these labels in more depth. Truth tables also test whether two statements are equivalent: build both final columns and compare. If they match in every row, the statements are logically equivalent, which is one way to prove [De Morgan's laws](/blog/de-morgans-laws-explained/).

## Where tables go wrong

1. **Too few rows.** Three variables in eight rows, never six. Recount the distinct letters before you start.
2. **Out-of-order input columns.** Use the halving pattern every time.
3. **Skipping intermediate columns.** Writing (p → q) ∧ ¬q in one step invites errors. A column per connective costs seconds.
4. **Treating "or" as exclusive.** The first row of p ∨ q is T.
5. **Reading the conditional backwards.** p → q and q → p differ in two rows. The [converse, inverse and contrapositive guide](/blog/converse-inverse-contrapositive/) shows which variants are equivalent.
